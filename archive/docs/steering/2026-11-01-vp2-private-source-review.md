## Selected geometry and mailbox proof

Scope must be B1,q_len8,window2048,page1,16Q/2KV heads,64dimensions. Grid32CTAs forms two16CTA clusters, one perKV head. Each rank owns token rank/2 and four heads from rank parity; both clusters cover every128(token,head) output row exactly once. Even ranks write their token's new KV for thatKV head once. Historical reads end before seq; the new block is computed from local normalized data and included causally, not read through racing cache stores. Per-query lower-window masks account for its token offset.

Each destination has16source records,1120B stride. Per source/owner:1024B output partials plus16B max and16B denominator, exactly1056B. The barrier expects16*1056=16896B. PV offsets end before1088, m occupies1088..1103 and l1104..1119; no overlap. Empty historical partitions still send zero PV and metadata, so they participate in completion.

`tools/test_vp2_mailbox_contract.py`:2CPU tests PASS, enumerating every lane/warp async-store destination byte, ensuring exact count/no duplicates/within bounds, plus output and cache ownership. This is integer ownership proof, not device execution or mathematical accuracy proof.

## Ordering and progress

Source5249–5253 initializes local mbm with arrivalcount1, publishes initialization with the cluster release fence, expects all bytes, and makes aligned cluster arrival. Source5400 waits acquire before remote stores. Each remote address and its completion barrier map to the SAME destinationCTA. Source5540 owner waits the local completion phase before generic local reads. WG1 retires WGMMA before issuing register-value PV stores. These are the mechanisms in [PTX st.async](https://docs.nvidia.com/cuda/archive/12.8.2/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-st-async) and [mbarrier completion](https://docs.nvidia.com/cuda/archive/12.8.2/parallel-thread-execution/index.html#parallel-synchronization-and-communication-instructions-mbarrier-test-wait-mbarrier-try-wait): st.async uses generic proxy and reports its stored byte count; observing completed barrier permits reads of its tracked stores. Do not remove any existing proxy/WGMMA/shared synchronization.

Every destinationCTA remains live until all incoming mailbox stores complete. No otherCTA reads its shared buffers after that receipt; outgoing values are register operands, not remote source-shared reads. All producer warp threads must finish issuing before theirCTA exits. Thus source review finds no need for an additional all-cluster exit barrier solely for these mailbox accesses. This reasoning depends on exact expected-byte/unique-destination coverage and unchanged participation. The [CUDA DSM lifetime requirement](https://docs.nvidia.com/cuda/archive/12.8.1/cuda-c-programming-guide/index.html#distributed-shared-memory) still applies. Local32CTA grid comprises two resident clusters; no software all-grid counter or queued-cluster progress dependency is present.
