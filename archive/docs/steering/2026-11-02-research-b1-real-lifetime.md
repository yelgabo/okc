## Conditional sufficient caller contract and failure boundaries

A sufficient contract would establish, for **every** graph or eager reader using this PR address: (1) a strong reference to the same mapping owner survives until the graph cannot be replayed again; (2) state/plan replacement, copies and exceptions preserve that owner or retire their readers; (3) all submission threads stop using the address before final release; (4) all already submitted readers and prepare copies complete successfully on the owning context; only then unmap/release/free on that context. The deleter may perform the final completion wait outside capture/timing, but cannot infer clauses1–3 merely from its own refcount reaching zero. No graph ownership cycle or process-exit retention is an acceptable substitute. The missing outer caller source or explicit evaluator guarantee is the smallest proof needed; passing one check would not prove the contract on exceptions/teardown.

Failure cleanup has distinct source boundaries:

- Reserve/create/map/access/property failure **before any GPU copy or captured reader** can safely unwind completed VMM stages in reverse order, checking each result and releasing each acquired resource once. Original PR/plans remain the fallback only if replacement has not committed.
- After a copy is submitted but before publication to any reader/graph, completion must be established before freeing the destination. An error exit alone is not that proof.
- After any prepare or judge graph can contain the address, clearing state or synchronizing in the deleter is insufficient unless that graph is also made permanently unreachable for future submission. Exception teardown needs the same ownership order. A failed synchronization or invalid/destroyed context cannot justify unmap; silent leak-until-exit is not the authorized design. Thus fail-closed diagnostics/retirement integration remain an explicit blocker, not solved by noexcept or CPU facade tests.
