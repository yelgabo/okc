# Bounded G O-boundary alternative: no second candidate

November1,2026. Source-only lane2 closure after expert→unpool PDL screening. ExactG0/607 source pins and profile rows are regenerated by `tools/attention_g_boundary_bounds.py`; [evidence](evidence/2026-11-01-g-boundary-alternative/bounds.json). No GPU/API call, code adoption, prototype, broad harness or performance claim. Root owns index/queue. The only currently surviving performance candidate remains the separately reviewed RMW representation; these audits do not count as additional candidates.

## Actual historical change

Pinned G0 has GLE_T={1:True}, GLE_B1X=True. Its actual D1 profiles contain GLE O-epilogue and _gle_route, without a separate b1 launch. Actual V1 profiles retain ordinary O, glue_cluster_boundary and _sl_tile_route. B1X wraps the router-writing b1 when its global weight pointer exists; unlike GLE_T it changes the router branch inside the retained boundary, not removal of that launch. The wrapper/source predication is relevant; the generic kernel name alone does not distinguish B1X math.607 has GLE_T={} and removes that B1X wrapper while retaining the normal short b1/FRT/route path. FORCE_GLUEV2False makes the older alternate boundary family irrelevant to this selected comparison.

The old GLE O epilogue BF16-rounds O, builds separately rounded u/v rows and polynomial norm partials, then projects those rows before recovering normalization scales in _gle_route. Required BF16 branch/preFFN rounding does not commute with those linear projections. The B1X router copy forms residuals from an unrounded post-norm branch (`nsx`), instead of the required BF16 branch used for the residual stream; the allowed unrounded FP32 final router vector does not authorize that earlier change. A fixed pointer or moved wait alone does not repair either algebraic rewrite. No blanket re-enable is proposed.

## Exact global cut a conforming replacement must retain

For each of8192 dimensions and every token:

1. O projection must finish as BF16, then global RMS1 uses all8192 O values (post-attention epsilon1e-8).
2. RMS1 output is BF16-rounded before channelwise alpha/beta residual formation. The FP32 residual s1 then determines a second full-row RMS (epsilon1e-5).
3. Effective preFFN coefficient applies after that RMS. Pooler h is BF16; router hr receives the corresponding unrounded FP32 normalized value. Both must derive from the SAME correct residual, not a second nsx branch.
4. Existing short optimization also materializes alpha2*s1 carry and a tail sum of its squared elements outside the first1024 columns for final _sl_cluster_finish. Preserve it and all coefficient interfaces.

The retained `_SL_GLUE_CUDA` makes these cuts explicit: native210 r1,218 BF16 bn,220–222 residual,233 carry,238 r2/tail,245 h and248–249 carry/router stores. `_graft` prepares the BF16 effective pre1 coefficient. Current b1 outputs8192*(2+4+4)+4=81924 bytes/token: BF16 h, FP32 hr/carry and tail. O itself remains16384 bytes/token. A correct fusion does not simply delete those live buffers: later FRT/route/final finish still consume them.

## Last-CTA completion is legally conceivable, not implemented

One possible distinct algorithm preserves the existing O tile's BF16 store, contributes a norm partial per token, and makes the unique last O CTA materialize the exact two-stage boundary. Producer contributions must be collected by the128 O compute consumers' NAMED barrier and a GPU acq_rel RMW/last-owner chain before coherent generic reads. It must NOT use a full288-thread CTA barrier: producer/escape warps have returned before this epilogue. The source-level publication argument follows the existing [PTX release/CTA relay proof](2026-11-01-g-ordering-restoration-proof.md); it is not validated merely by a source resemblance.

A last-owner design needs no inter-CTA spinning: nonlast CTAs retire, and the last arrival alone reads all O values/partials. The counter/partials must be private mutable prepared/graph storage with complete input overwrite, generation or same-stream reset proof, and no same-state concurrent replay assumption. Every writer's store must precede its release, and the last acquire must precede final reads. Mutable loads cannot use __ldg/.nc. Preserve existing async MMA/TMA/escape completion and proxy fences before reusing any shared ring; a last flag alone does not retire async readers.

For256 O CTAs the extra RMS partial buffer is1024 bytes/token each direction. Much larger h/hr/carry traffic remains. Reusing the O tile in registers saves only that last CTA's own32 output dimensions; the other tiles still require global publication/read. Saving a separate launch is plausible, but zero-byte/global-norm arithmetic is not.

The actual b1 launch uses8 CTAs/token,128 threads/CTA. Last-owner fusion collapses that parallel work to ONE128-compute-thread CTA for T1 or T8. T1 alone needs64 residual values/thread if retained across RMS2; preloading additional vectors creates substantial register/liveness pressure. T8 needs sequential row processing or extra shared/global staging. A ring-reuse, warp-per-row or multi-pass plan has not been compiled or benchmarked. Extending the old T1-only change to T8 is therefore a new architecture, not a recovered source optimization with known cost. No resource/admission/occupancy or correctness clearance follows from this concept.

## Score screen and stopping decision

Exact607 b1 profile activities, one call per cell: D1sliding/full3.4/3.3us; V1sliding/full3.0/3.2us. With exact owning benchmark denominators and46:16/six-load scoring, hypothetically setting those D1 activities to ZERO gives factor1.007344582. Setting BOTH short loads' activities to ZERO gives1.011830739 before ANY replacement finalization cost. These are conditional profile-substitution screens, not exposed gains, hard hardware ceilings or same-input paired estimates. The previously reported short-glue cross-job gap below1% is also not recoverable critical-path time.

Thus the historical T1-only launch-removal scope misses the registered1% screen even in its artificial zero-cost case. Extending to T8 leaves only roughly0.18percentage-point margin before replacement work, while collapsing substantial parallelism and preserving nearly all live outputs. There is no defensible material bounded implementation from current evidence. Stop this lane without a prototype or GPU request; do not fabricate a second candidate to satisfy breadth.

Reopening would require a concrete complete boundary mapping with all precision/publication/ownership proofs and an actual source/compiler cost screen suggesting a materially cheaper finalizer, followed by same-input complete-graph measurement. The old algebraic rewrite, unsafe B1X, closed overlap/MFIN/locality variants and unrelated tuning remain closed. Keep readiness review of the common single-arm qualifier separate: fail-closed startup can qualify an authorized measurement without inventing a gain or waiting for private performance quota.
