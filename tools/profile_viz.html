okc profiles

Where each of our kernel-challenge runs spends its time, compared with SGLang (the code we have to beat) and with the hardware's speed limit. Pick a problem, then read the rows from the top.

What do these words mean?
problem
One piece of the model we rewrite, for example the MoE step or the attention step. Each tab is one problem.
run
One okc check: the judge times our code on every shape of the problem and gives it one score.
shape
One input size the judge times. "decode, 16 users" means 16 users each generating one token, so the code processes 16 tokens in one call. "verify" means each user checks 8 guessed tokens at once, so 16 users is 128 tokens.
kernel
One function that runs on the GPU. Our code for one shape launches several, one after another; each coloured piece of a bar is one kernel.
floor
The fastest the shape could possibly run: the bytes it must read divided by the GPU's memory bandwidth (or the maths divided by its peak, if larger).
score
How many times faster than SGLang we are, averaged over the shapes (a weighted geometric mean). Above 1.0x beats SGLang.
sliding / full
The two kinds of attention layer in Muse: sliding looks back 2,048 tokens, full looks back over the whole 80,000-token context.

How to read a row

  1. 1Thick bar: our code. Each coloured piece is one GPU kernel, left to right in the order they ran. A longer piece took longer. The number after the bar is our total time.
  2. 2Thin bar: SGLang's code, split the same way, so you can compare piece by piece.
  3. 3Solid line: SGLang's total time. If our bar ends left of it, we win that shape.
  4. 4Green line: the floor. Nothing can end left of it. The space between it and our bar's end is what is left to win.

Which kernel to speed up first

Each kernel that ran, best target first. The last column is the score this run would get if that one kernel were twice as fast everywhere it runs. The score averages per-shape speedups, so what counts is how much of each shape's time a kernel takes and how much those shapes weigh, not its raw microseconds: 10 µs that is all of a short, heavily weighted shape beats 300 µs that is part of a long, lightly weighted one.
