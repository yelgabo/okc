## One concrete alternative: G2/24, three rings, two independent producer fronts

Current selected source: `muse_decode_layer/cand/g1b4_stage_release.py` SHA256 `ba9e327cd7b96595ace4d0c1d0d78fe27c128f23ed0debcda97c7169fc3164ab`; actual `MOE_CUDA_SRC` SHA256 `c7c201ae145c6a33f2d5e6b1f80d2a6e56e8d75502f9fd09ace40927ad0f7c71`. The common-OFF source pin remains `4cbb13a9a359c9fe870a94ebcabc4706447778849f71d4aa54e47d69abbd1280` from the prior audit; selected native arithmetic is not replaced. MAIN/B4 targets are D32=M32/B4, V16=M128/MAIN, V32=M256/MAIN, sliding/full. Other selected routes remain untouched, including Tiny/Tiny2 and the worker's seam.

Current G uses four compute WGs, two helper warps,576threads, three weight and three activation slots,231168B shared per CTA, one CTA/SM. Each256-weight-row unit has16K256 stages. WGs dequant their own64rows into RS operands; phaseA computes gate/up + SiLU and publishes xB, phaseB down/norm follows per-stage doneAs dependencies. It already overlaps phaseB with other CTAs' phaseA tails. No nonexistent global A/B barrier is removed by this proposal.

G2/24 would keep the RS mainloop, exact dequant and GS2 pipeline, but use **two compute WGs + the same two helper roles =320threads/CTA**,128-weight-row units, token jobs capped at24, and a cooperatively admitted grid of `2 * SM_count`. Two CTAs provide four compute WGs/SM as before but two independent weight/x producer queues and independent stage readiness; one stalled helper/front need not park all four WGs. It removes no necessary arithmetic or global intermediate. Its only proposed saving is hiding previously exposed producer/readiness stalls or smoothing tails. Existing evidence does not measure that exposed interval.

This is deliberately NOT an `OKC_NW`/grid tweak. Actual source currently rejects or misaddresses such a change:

- Each new A unit produces64 intermediate columns. Four A units x two WGs feed a256-column B stage: **eight release publications remain required, but the parent becomes ub>>2, not ub>>1**. - Native weight storage can be addressed by old unit `new_ub>>1`, half `new_ub&1`, same stage, two consecutive original WG pieces. Retain exact SC6/non-SC6 byte treatment and KPERM3 reuse; blindly replacing WGS_STG and multiplying new_ub by that value selects the wrong existing packed layout.
- Fixed FT_T24 is supported by the active job-builder's division/chunk logic (not a power-of-two mask), but JMAX168 exceeds both unconditional MF_XRS96 and literal136-job doneAs allocation. Resize/rebase the EXISTING scratch flag/fixup regions, preserving replay zeroing/parities; do not waive asserts. Current grid<=SM_count/grid<=136 and160fixup slots reject the264-CTA H200 grid. Two-WG slots need capacity>=grid+1 and all initialization/ownership formulas updated. No new global replacement buffer is proposed.
- Only NTT1..3 is reachable; current unconditional wider WGSMMA specializations/switch arms cannot be assumed safe when WGS_NT shrinks. Guard/prune unreachable wider instantiations rather than compile out-of-range accumulator references.

Numerics remain mandatory: NVFP4 decode and group16 scale multiplication, FP32 accumulation, BF16_RNE gate/up before SiLU, exact selected FP32 exp/div/up multiply and final BF16, down BF16/norm/effective-gamma boundaries, routing weights and combine. Changing Stream-K partitions can change FP32 partial-sum grouping; this is not bitwise equivalence by assertion. Prove retained boundaries and separately qualify permitted numerical tolerance on split/nonsplit/finalizer paths. Original SwiGLU BF16 output was already present; no mythical round tax is removed.

Progress is a **remaining implementation proof obligation**, not established by shared-memory fit. Runtime occupancy must admit the whole cooperative grid (no optimistic co-residency assumption), and new unit/range mapping must preserve trailing-partial-first phaseA, designated split finisher, empty routing, zero-length segments, terminal WgsPend drain and all helper completion obligations. More CTAs alone cannot repair a cross-CTA dependency cycle. Existing per-stage proof cannot simply be copied with hardcoded parent/slot IDs left unchanged. This is why the report supplies a bounded design, not ready-to-run source.

## Why not the tempting separate decoder

A decoder WG + SS WGMMA is not a free overlap transfer. It retains exact dequant arithmetic, adds64 decoded K64 fragments x32768B write+32768B tensor read =4194304 logical shared bytes per256-row K4096 unit, requires another producer/consumer lifetime, and pressures the rings/register budget. Existing P3/cw `4922f366a0c142ca` already measured a different shared BF16 reconstruction pipeline losing without useful decode/compute overlap; the old MoE audit P1 likewise required a full activation-traffic design, not an isolated decoder. Neither proves all SS designs impossible, but no new exposure evidence here justifies reopening that fixed graft. Chord/Humming's inspected complete cores keep dequant on consumers; their improvements cannot be cited for dedicated-decoder overlap.

**Handoff:** fixed G2/24 is the strongest concrete alternative from this bounded pass, but remains a design, not an implemented/qualified contender. My recommendation is HOLD its build/check until captain explicitly accepts its high engineering cost and unresolved materiality; if a broader build is funded, use the single discriminator above.
