## What the source establishes

The kernel swaps expert and token axes, uses separate weight/activation TMA producers and `tcgen05` accumulation into TMEM, then combines cluster K slices through DSMEM. Its output is FP32, but operands are rounded to TF32 on input. The [serving tables and eligibility gate](https://github.com/wookjeHan/sglang/blob/07e2f70fa9de868aef4c2c35f0a4da0d6000f6e1/python/sglang/kernels/ops/gemm/muse_spark_router_gemm_cutedsl.py#L792-L891) admit only configured SM103/SM107 ranges with 2–1024 tokens and TF32 allowed. M1 retains GEMV. Under `highest` precision it declines. The [model dispatch](https://github.com/wookjeHan/sglang/blob/07e2f70fa9de868aef4c2c35f0a4da0d6000f6e1/python/sglang/srt/models/muse_spark.py#L247-L261) tries the existing GEMV before this kernel and retains the linear fallback.

This is a Blackwell source reference. Its published gate excludes H200. A Hopper version and a matched precision/correctness comparison would be required before considering it here. Our recently diagrammed public607 router uses FP32 FMAs inside the fused pooler/router, so matching only the matrix dimensions would not match the numerical contract. No immediate adoption or new experiment allocation follows.

## Discussion and caveats

A [public review comment](https://github.com/sgl-project/sglang/pull/47636#discussion_r4452778085) flags unconditional CuTe/CUDA imports that can break model import on ROCm. Source inspection confirms the eager import chain. No ROCm execution or CI failure was reproduced here. Treat the patch as an unmerged reference, with this portability issue still raised.

The related [gather/norm/quant fusion PR47517](https://github.com/sgl-project/sglang/pull/47517), pinned at `6cec38eababd6cb884bc91829f28e5f6adab8db7`, reports that shortening the main stream can leave expert start unchanged while the router gates it. [Routing metadata PR47561](https://github.com/sgl-project/sglang/pull/47561), pinned at `c9984c09ee3fc1d3f2022a5127e75c8ad5d60ee1`, changes where that metadata runs. These are serving-path observations with collectives and auxiliary streams. Their gains cannot be added to single-GPU kernel-track timings.
