## Actual lowering and strongest limitations

Independent inspection of all four published PTX archives confirms normalized Tiny/Tiny2 code differs only at the one intended acq_rel.s32→relaxed.u32 ATOM. It returns old into a register used for last-arriver comparison; it is not a returnless RED. Explicit preceding membar.gl and final ld.acquire.gpu.global.b32 remain. The unsigned counter representation is identical over0..G. [Compiled proof/load census](evidence/2026-11-01-g-ordering-restoration/compiled-proof-census.json); reproducer `tools/attention_g_counter_ptx_audit.py`.

PTX memory-model scope excludes noncoherent loads, so this was checked rather than assumed: each selected post-counter path has16 ld.global.cg.f32 ss loads and16 ld.global.cg.v4.f32 ybuf loads, and ZERO ld.global.nc anywhere after this counter. Other post-counter loads are generic input loads. Source finalizer uses __ldcg. The removed CCTL.IVALL belongs to the acq_rel-ATOM lowering block; the explicit final acquire remains. No texture/noncoherent-cache contract is invoked. Async slot/publication fences remain a separate prerequisite; this generic-counter proof does not order across proxies by itself.

Peer local CUDA12.8 compiler evidence reports147 registers/3 barriers/zero stack/spills for both arms of Tiny/Tiny2, with intended ATOM-lowering block and tail padding differences. SASS is NOT wholly identical: the implicit RMW memory-order block changes, while explicit PTX fences, all math and joins remain. No H200 latency/utilization/capture proof follows. Independent MoE audit also checked the WSBL tail relay and counter generation. Hardware/compiler preservation of the documented PTX semantics is assumed; this is not a simulator/model-checker proof of the entire unchanged kernel.
