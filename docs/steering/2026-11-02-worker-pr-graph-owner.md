## Actual ownership construction

The host allocator checks source CUDA/BF16/contiguous exact shape, prepare outside capture, current/source device and primary context, VMM/compression capabilities, granularity, byte/rounding overflow, VA reservation, physical handle, actual backing properties, mapping/access and pointer alignment. Actual GENERIC/type/device properties must match; requested flags alone never label success. It copies source bytes with cuMemcpyDtoDAsync and completes that prepare copy on its stream before exposing the tensor or plans. Public at::from_blob preserves sizes/strides/device/dtype over the private address; supplied/default allocations are untouched.

One CUDA user object starts with **one caller reference**, owned collectively by the from_blob storage deleter, not one per Python Tensor alias. The mapping record contains a handle value but does not own an additional CUDA user reference. The detached worker keeps the raw allocation record alive until its release signal; it does not retain a user-object reference. Thus neither a state/graph ownership cycle nor a process-lifetime allocation registry is introduced.

Every tagged actual _graft_lt_run checks pointer/shape/stride/dtype/device against its immutable owner, then queries the caller's current stream using the full CUDA13 seven-argument cuStreamGetCaptureInfo signature. Query/context/invalidated/unknown-status/retain failure throws BEFORE Lt pointer submission. Active capture attaches one graph-owned user reference with flags0 before the read; eager mode does not fabricate a graph reference. The fresh process-unique capture ID is retrieved, but no graph handle or capture-ID dedup cache exists: repeated reader attachments intentionally add balanced CUDA-managed references. Borrowed graphs are never destroyed, nodes/edges/executables are not changed, and no global PyTorch graph hook is installed.

CUDA-managed clone/executable/update/deferred-inflight retention is the conditional primary API mechanism accepted in fcf5452, not something proved by local tests. The adapter never manually removes those graph references. At final tensor-storage deletion only the one caller reference is released. CUDA's final user-object callback performs **one release-store to an atomic boolean only**. A C++17 static assertion requires that boolean signal to be always lock-free. It calls no CUDA, frees no last shared owner, allocates no queue node, joins no thread and waits for no acknowledgement.

One worker thread per mapping polls that flag, then pushes its retained primary context, waits for preceding context work, unmaps/releases/frees acquired resources in reverse order, pops context and releases its context lease. Eager submission holds its plan/tensor owner through the host call; after all host storage and CUDA graph references retire, there is no valid future eager/graph reader of that address. The context completion step covers prior eager/copy work outside captured/timed execution. This relies on valid serialized graph operations, not arbitrary external graph-pointer edits or forcibly resetting a live device.

## Failure, fallback and cleanup policy

Unsupported layout/context/capability, nongeneric backing or checked setup errors return a tagged no-treatment result **after successful safe rollback**, leaving original PR/plan fallback intact. Allocation stages unwind only acquired mapping/handle/VA/context resources. Once a copy may have been enqueued, cleanup requires context completion before freeing. A failed read-retention hook stops before compressed Lt execution; it never silently treats failure as eager mode. CUDA owns attached graph references through capture abort/destruction; no cached graph handle is revisited during unwind.

Cleanup/context/completion/user-reference-release errors are **fatal, no-throw process stops**, with PR_GRAPH_FATAL diagnostics; they never authorize unsafe unmap or an indefinite resource quarantine. Unexpected tensor-wrapper/return publication failure after worker handoff is also a fatal stop, not a recoverable fallback. Thread/detach/runtime shutdown failures are not claimed as successful recovery. This deliberately severe error policy is part of the source artifact and must be reviewed before any target allocation. CPU models do not exercise native abort, actual callback scheduling or CUDA error propagation. No leak-until-process-exit policy is used for normal mapping retirement.

Tagged plan deepcopy preserves the SAME immutable weight and owner while using the original deepcopy behavior for unrelated members. Pointer/shape/stride/dtype/device mismatch fails closed. Untagged plans use original deepcopy. Independently prepared states allocate independent owners; shared read-only plan clones do not create a falsely labeled unowned mapping.
